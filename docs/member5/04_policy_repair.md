# 策略校验与修复

当前生成和更新的异常重试会提高温度并复用输入。校验错误没有作为反馈写回模型提示词。下面记录现有解析入口和独立校验器，它们可作为后续修复的接入点。

| 项目 | 内容 |
| --- | --- |
| 文件路径 | `secagent/utils.py:5` |
| 函数名称 | `extract_json` |
| 调用者 | 初始生成和更新函数 |
| 输入参数 | `text` 实际为 `str`，`enforce_code_block` 默认 `False` |
| 输出 | JSON 解析值或 `None`，无效 JSON 抛出 `JSONDecodeError` |
| 核心逻辑 | ① 去除首尾空白。② 识别 No 前缀并返回空。③ 优先读取 JSON 代码块，按配置拒绝无代码块输入。④ 对裸文本去除可选 Yes 前缀并解析 |
| 依赖函数 | `re.search`、`json.loads` |
| 当前不足 | 合法 JSON 与合法策略结构是两项不同检查，现有解析器只做前一项。跳过与缺少必需代码块都可返回空 |
| 改进计划 | 区分跳过与解析失败，在上层对策略列表及必填键给出结构化反馈 |
| 测试方法 | 覆盖裸 JSON、代码块、No、损坏 JSON 与合法 JSON 但错误结构 |

| 项目 | 内容 |
| --- | --- |
| 文件路径 | `secagent/policy_type_check.py:79` |
| 函数名称 | `security_policy_type_check` |
| 调用者 | 同文件示例。生成与更新未调用此实现，`secagent/tool.py` 的同名函数目前只整理工具字典 |
| 输入参数 | `security_policy` 为工具名映射到规则列表，亦可为 `None`。 `available_tools_dict` 为工具名映射到参数定义的字典 |
| 输出 | 警告字符串列表 |
| 核心逻辑 | ① 遍历策略工具与规则。② 检查工具名和参数名。③ 对字典限制选取 JSON Schema 校验器。④ 递归检查类型专用关键字并汇总警告 |
| 依赖函数 | `validator_for`、`check_schema`、`check_type_specific_keys` |
| 当前不足 | 未知工具带参数时，记录警告后仍直接索引工具字典，可能抛出 `KeyError`。现有生成链未消费诊断 |
| 改进计划 | 修复未知工具分支，接入提交前检查，将诊断用于有限次数修复，失败时保留旧策略 |
| 测试方法 | 用未知工具、未知参数和类型关键字冲突检查诊断。固定一次失败后修复成功的模型响应，验证提示词携带错误位置和原子写回 |
