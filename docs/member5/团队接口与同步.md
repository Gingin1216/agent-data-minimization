# 成员 5 授权接口与同步

> 维护：成员 5  
> 用途：供成员 3 接入执行器，供成员 4 读取已生效授权与追踪版本。

## 一、会话与生效策略

| 问题 | 当前约定 |
| --- | --- |
| Session 保存哪些范围 | `PolicySession.authorized_data_scopes` 已可读取当前数据库授权。快照和 Session 的 `authorized_file_scopes` 目前返回空元组，文件授权等成员 3 确定类型后再发布 |
| 成员 4 从哪里读 | `get_authorization_snapshot(session)` 一次返回 `session_id`、`task_id`、`policy_version`、`effective_rules` 和有效范围。返回值与会话状态隔离，一次工具访问使用同一份快照 |
| 策略记录如何同步 | 发布成功后，`PolicyRecord.data_scopes` 从同一发布版本填充。生成和更新沿用可信范围。拒绝的模型候选保留诊断，生效版本继续使用 |
| 谁初始化 | 可信任务宿主或适配器调用 `create_policy_session(task_id=..., user_identity=..., user_query=..., authorized_data_scopes=...)`。任务编号来自可信 TaskSpec，用户身份来自认证或可信评测上下文。宿主传入已经过权限和任务边界核对的范围 |
| 如何保持版本一致 | `publish_policy(session, rules, expected_version=..., authorized_data_scopes=...)` 一次发布规则、范围和新版本。省略范围时沿用当前范围，传空元组可撤销数据库授权。提交时版本冲突抛出 `PolicyVersionConflict` |

`publish_policy` 的范围参数仅供可信代码使用。它校验 DataScope 数据结构；可信宿主负责判断传入范围是否有授权依据。模型候选只修改工具规则。首轮测试用 `DB-001` 的人工标注作为测试授权。

## 二、成员 3 和成员 4 怎么接

1. 成员 3 在数据库执行前调用 `check_database_access(session, tool_name, args, field_types_by_table, database="company")`。字段类型来自可信 Schema，键为 `(database, table)`。
2. 入口用同一份快照执行工具规则检查和成员 4 的 `sql_to_scope()`、`check_data_scope_set()`。执行器只接受 `PROVED`，并执行刚检查过的同一份 SQL 与参数。`VIOLATED`、`UNKNOWN` 和缺失授权均在查询前拒绝。
3. 成员 3 限制输出字段和返回行数，把实际返回范围补入 `DecisionTrace.actual_returned_scope`。工具调用的三态结果、请求范围和已授权范围留在 `DecisionTrace`，通过 `session_id + policy_version` 关联发布记录。实际返回范围由执行器根据结果填写。

辅助接口已公开。成员 3 的正式 SQLite 工具、Schema 版本绑定、结果裁剪与审计落盘仍待联调。文件工具需先确认 `FileScope`、工具签名、`file_id` 映射及操作语义。

## 三、适配器接线

| 框架 | 会话传递 |
| --- | --- |
| AgentDojo | `run_task_with_pipeline(..., policy_session=session)` 绑定本次任务上下文。初始生成、已有工具包装和结果更新读取同一会话，重试沿用该会话 |
| LangChain | `run(..., session=session)` 将会话传给工具注册、初始生成和工具中间件 |
| OpenAI Agents | `run(..., session=session)` 将会话传给 Agent 包装器、本地与 MCP 工具包装、初始生成和结果更新 |
| MCP 代理 | 启用 SecAgent 时，可信宿主在代理进程内以 `with bind_policy_session(session) as token` 注册本次运行；受保护的 REST 请求和 MCP 请求携带 `x-progent-policy-token`。工具列表与调用解析同一绑定。缺失或失效绑定拒绝访问，退出时 token 立即注销 |

MCP 目前提供进程内注册接口。独立启动的代理 CLI 仍需可信任务宿主接入注册流程，客户端单独传 `task_id` 不会建立绑定。
