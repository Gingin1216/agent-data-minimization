# 成员 5 授权接口与同步

> 维护：成员 5  
> 用途：供成员 3 接入执行器，供成员 4 读取已生效授权与追踪版本。

## 一、会话与生效策略

| 问题 | 当前约定 |
| --- | --- |
| Session 保存哪些范围 | `PolicySession.authorized_data_scopes` 已可读取当前数据库授权。快照和 Session 的 `authorized_file_scopes` 目前返回空元组，文件授权等成员 3 确定类型后再发布 |
| 成员 4 从哪里读 | `get_authorization_snapshot(session)` 一次返回 `session_id`、`task_id`、`policy_version`、`effective_rules` 和有效范围。返回值与会话状态隔离，一次工具访问使用同一份快照 |
| 策略记录如何同步 | 发布成功后，`PolicyRecord.data_scopes` 从同一发布版本填充。生成和更新沿用可信范围。拒绝的模型候选保留诊断，生效版本继续使用 |
| 谁初始化 | 可信任务宿主或适配器调用 `create_policy_session(task_id=..., user_identity=..., user_query=..., authorized_data_scopes=...)`。任务编号来自可信 TaskSpec，用户身份来自认证或可信评测上下文。宿主传入已经过权限和任务边界核对的范围 |
| 如何保持版本一致 | `publish_policy(session, rules, expected_version=..., authorized_data_scopes=...)` 一次发布规则、范围和新版本。省略范围时沿用当前范围，传空元组可撤销数据库授权。提交时版本冲突抛出 `PolicyVersionConflict` |

`publish_policy` 的范围参数仅供可信代码使用。它校验 DataScope 数据结构；可信宿主负责判断传入范围是否有授权依据。模型候选只修改工具规则。首轮测试用 `DB-001` 的人工标注作为测试授权。

## 二、成员 3 和成员 4 怎么接

1. 成员 3 在数据库执行前调用 `check_database_access(session, tool_name, args, field_types_by_table, database="company")`。字段类型来自可信 Schema，键为 `(database, table)`。
2. 入口用同一份快照执行工具规则检查和成员 4 的 `sql_to_scope()`、`check_data_scope_set()`。执行器只接受 `PROVED`，并执行刚检查过的同一份 SQL 与参数。`VIOLATED`、`UNKNOWN` 和缺失授权均在查询前拒绝。
3. 成员 3 限制输出字段和返回行数，把实际返回范围补入 `DecisionTrace.actual_returned_scope`。工具调用的三态结果、请求范围和已授权范围留在 `DecisionTrace`，通过 `session_id + policy_version` 关联发布记录。实际返回范围由执行器根据结果填写。

辅助接口已公开。成员 3 的正式 SQLite 工具、Schema 版本绑定、结果裁剪与审计落盘仍待联调。文件工具需先确认 `FileScope`、工具签名、`file_id` 映射及操作语义。

## 三、适配器接线

| 框架 | 会话传递 |
| --- | --- |
| AgentDojo | `run_task_with_pipeline(..., policy_session=session)` 绑定本次任务上下文。初始生成、已有工具包装和结果更新读取同一会话，重试沿用该会话 |
| LangChain | `run(..., session=session)` 将会话传给工具注册、初始生成和工具中间件 |
| OpenAI Agents | `run(..., session=session)` 将会话传给 Agent 包装器、本地与 MCP 工具包装、初始生成和结果更新 |
| MCP 代理 | 启用 SecAgent 时，可信宿主在代理进程内以 `with bind_policy_session(session) as token` 注册本次运行；受保护的 REST 请求和 MCP 请求携带 `x-progent-policy-token`。工具列表与调用解析同一绑定。缺失或失效绑定拒绝访问，退出时 token 立即注销 |

MCP 目前提供进程内注册接口。独立启动的代理 CLI 仍需可信任务宿主接入注册流程，客户端单独传 `task_id` 不会建立绑定。

## 五、任务需求比较与 Agent 反馈

三类范围现已分别保存在同一版本的快照中。

| 输入 | 正式读取方式 | 状态 |
| --- | --- | --- |
| 授权范围 | `get_authorization_snapshot(session).authorized_data_scopes` | 已接入 |
| 禁止范围 | `get_authorization_snapshot(session).forbidden_data_scopes` | 已接入，从可信 TaskSpec 的 `forbidden_scope.datascope` 初始化 |
| 任务必需范围 | `get_authorization_snapshot(session).required_data_scopes` | 已接入，首轮人工提供 `must_visit.datascope` |

`create_policy_session()` 和 `publish_policy()` 均接受上述三个独立参数。发布时省略禁止和必需范围会保留原值，传空元组可清除。记录中同步保留三类范围。

`check_database_access(..., comparator=compare_task_scopes)` 调用成员 4 提供的函数，关键字参数为 `requested_scopes`、`authorized_scopes`、`forbidden_scopes`、`required_scopes`、`field_types_by_table`。返回类型暂定为公开的 `TaskScopeComparison`，成员 4 的正式实现接入时可加转换适配。

返回对象分别包含授权包含、禁止范围无冲突、读字段充分、输出字段充分、记录充分、字段最小、记录最小七项结果。每项使用现有 `ScopeCheckResult` 的状态、错误码、原因和证据格式，并另存缺失和额外字段、遗漏和多申请记录范围。各项以正向要求命名，`PROVED` 表示该项要求满足。

`DecisionTrace.comparison` 保留分项结果，`feedback` 用于向 Agent 返回问题，`session.decision_traces` 保留每次尝试。统一重试入口为 `run_database_access_with_feedback(..., comparator=..., executor=..., retry_agent=...)`，最多两次纠错，只有授权检查及七项比较全部为 `PROVED` 才调用执行器。Agent 回调接收原参数与反馈，生成新的 SQL 参数。现有框架需在数据库工具执行入口调用此包装入口，通用框架工具中间件尚未自动消费该回调。

仓库尚无成员 4 的任务比较实现。带禁止或必需范围时，缺少比较器返回 `UNKNOWN / comparator_unavailable`，阻止执行。当前新增测试使用固定比较结果验证输入、反馈与记录，实际比较算法需成员 4 提供后联调。

可运行的初始化样例位于 `docs/member5/db001_integration_example.py`。它读取可信基准生成器中的角色权限及员工部门，构造部门经理对本部门报销的授权（200 行上限，含 category），再分别读取 TaskSpec 的禁止与必需范围（任务上限 20）。三类范围具有独立来源。

本轮根目录测试为 33 通过、0 失败，保留两条原有弃用警告。

## 六、2026-11-20 SQLite 真实联调

已核对工作区中成员 3 的 `sqlite_schema_adapter.py`、`sqlite_guarded_executor.py`，以及成员 4 的 `datascope_forbidden.check_forbidden_scope_set()` 和 `task_scope_comparator.compare_task_scopes()`。统一入口默认加载真实比较器；禁止状态未初始化或比较器缺失时拒绝。本轮未查询 Git 分支状态。

初始化通过 `create_policy_session(..., forbidden_data_scopes=...)`，显式空列表表示可信确认无禁止范围；省略或传 None 表示尚未确认。加载失败时宿主必须停止初始化，不发布生效会话；非法发布抛出异常，旧版本保留，不把错误转换为空授权。禁止状态标记为快照的 `forbidden_data_scopes_initialized`。

执行器兼容桥接函数现在只转发统一入口的分项检查结果，避免重复执行禁止范围组合。一次调用捕获一份快照并传给检查器。桥接核对 trace 的任务、会话和版本，混用版本拒绝；检查后发布新版本仍按开始时的版本完成本次执行。

结果接口为 `record_database_result(session, trace, *, actual_columns, actual_row_count, db_version, env_hash)`，返回补全的 DecisionTrace，并以 `decision_id` 更新会话中的原检查记录。执行器已调用此接口。实际列和行数必须满足已检查的投影和上限；传入其他会话或未通过的检查结果会被拒绝。`actual_returned_scope` 仍保留为可选 DataScope，列名和行数不足以证明实际记录谓词，因此本轮保留为空，观测值存入明确的元数据字段。

完整 DB-001 数据在临时 SQLite 文件中生成，正常返回 16 行，金额合计 13412.33。真实执行器和比较器验证未授权 remark、其他部门、LIMIT 201、已授权字段命中显式禁止、缺失 Session、未初始化和加载失败均拒绝；SQLite trace 验证拒绝时未运行 Agent SQL。另验证新策略发布后，当前结果仍记录原检查版本。版本混用拒绝由桥接接口测试覆盖。

复现命令为 `.member5-venv/Scripts/python.exe -m pytest -q -p no:cacheprovider tests`。联调样例初始化函数仍在 `docs/member5/db001_integration_example.py`，提供工具规则及三类范围。测试通过不代表真实模型或四个 Agent 框架已完成数据库工具接入。

## 八、真实数据库 Agent 入口

`secagent.database_agent.run_database_agent()` 已提供给成员 2 的实验运行器。可信宿主传入 client、model、session、GuardedSQLiteExecutor、用户请求和可信 Schema 描述。Agent 通过真实 OpenAI 兼容工具调用协议自行生成 SQL，统一执行器检查通过后查询，拒绝时以 tool 消息反馈检查类别和错误码。最多三次申请，报告记录 SQL 申请、版本、decision_id、结果及审计元数据。模型仅接收任务、身份和 Schema，不接收 reference_sql、标准答案或 required_scopes。

DB-001 CLI 为 `docs/member5/real_database_agent.py`。先由可信宿主运行模拟环境初始化脚本生成 company.db，然后在配置国内兼容服务凭据的同一终端运行：

```powershell
.member5-venv/Scripts/python.exe data_minimization_benchmark/environment/database/init_db.py
.member5-venv/Scripts/python.exe docs/member5/real_database_agent.py --model deepseek-chat --commit 手动确认的提交号 --output docs/member5/real_database_agent_result.json
```

初始化命令会重建模拟 company.db，应在测试环境中执行。CLI 只读现有库，并校验 TaskSpec 指定的环境版本及指纹，指纹不匹配时应由成员 1 核对环境和任务版本。

新增测试 2 项通过，使用固定模型响应、真实 SQLite 执行器及真实比较器，覆盖缺输出字段后修复成功和连续三次拒绝。当前入口采用可信宿主已发布的策略；策略生成/动态更新仍使用既有接口，未在该 Agent 循环中自动修改授权。
